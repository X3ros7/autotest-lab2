# Відповіді на контрольні запитання

## 1. Наведіть особливості TDD підходу

- Тест пишеться раніше за код.
- Робота йде циклами Red, Green, Refactor:
  - Red: тест для нової поведінки, який має впасти.
  - Green: мінімальний код, що проходить усі тести.
  - Refactor: покращення коду без зміни поведінки, тести лишаються зеленими.
- Кроки малі, зворотний зв'язок швидкий.
- Пишеться лише той код, який потрібен тестам.
- Тести є документацією та регресійним захистом, рефакторинг безпечний.
- Пишучи тест, розробник спершу проєктує API з боку користувача.
- Недоліки: потрібні час і дисципліна, складно для UI та коду із зовнішніми залежностями.

## 2. Як модульне тестування використовується у методології TDD?

- Модульний тест є рушієм розробки: кожен цикл охоплює одну малу одиницю поведінки (метод класу).
- Падіння тесту (Red) є підставою писати код, зелений тест (Green) є критерієм готовності.
- Під час Refactor набір тестів доводить, що поведінка не змінилась.
- Тести накопичуються і запускаються після кожної зміни, швидко виявляючи регресії.
- Тест фіксує інтерфейс, результат та помилки до появи реалізації.

## 3. Як враховується специфікація програмного забезпечення та на якому етапі?

- Специфікація пишеться першою, до тестів і коду.
- Кожна вимога розбивається на перевірювані приклади: типовий випадок, граничні випадки, помилки.
- На етапі Red тести пишуться безпосередньо зі специфікації, тому кожен тест простежується до вимоги.
- Під час Green і Refactor специфікація лишається критерієм правильності.
- Якщо під час розробки виявляється неповнота, спочатку оновлюється специфікація, потім пишеться тест.
